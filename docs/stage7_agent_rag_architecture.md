## 2. Critical Architectural Rule: No LLM Numerical Decisions

> [!IMPORTANT]
> **LLMs must NEVER make numerical decisions, calculate costs, or alter optimization outputs.**

### 2.1 Authorized LLM Agent Functions
Stage 7 AI Agents are strictly limited to:
* **Evidence Retrieval**: Fetching relevant domain documents, rule references, and pipeline metadata.
* **Plan Summarization**: Explaining the selected optimal charter schedule in plain language.
* **Alternative Comparison**: Comparing pre-computed scenario results generated by Stage 6.
* **Risk Identification**: Explaining documented delay or congestion risks retrieved from Stage 3/5.
* **Question Answering**: Answering operational queries using validated evidence.
* **Optimizer Rationale**: Explaining why the CP-SAT solver prioritized feasibility over delay penalties.

### 2.2 Prohibited LLM Agent Actions
Stage 7 AI Agents must **NEVER**:
1. **Modify Freight Forecasts**: Change Stage 2 predicted freight rates.
2. **Calculate / Override Costs**: Calculate or alter charter rates, fuel costs, insurance, or port fees.
3. **Override Feasibility**: Alter Stage 4 feasibility evaluations (`FEASIBLE`, `INFEASIBLE`, `DATA_UNAVAILABLE`).
4. **Invent Vessel Physical Specs**: Fabricate vessel DWT, LOA, beam, draft, or physical IMO numbers.
5. **Invent Indian Port Congestion**: Represent `GLOBAL_CONGESTION_PROXY` as verified Indian port congestion.
6. **Invent Charges**: Invent bunker surcharges, insurance penalties, or canal charges.
7. **Modify Optimization Results**: Alter allocated cargo quantities or objective values.
8. **Convert Unavailable Statuses**: Turn `DATA_UNAVAILABLE` into numerical estimates.

## 3. Core Data Contracts (`src/agents/contracts.py`)

All contract data classes are typed, serializable (`to_dict()`, `from_dict()`, `to_json()`, `from_json()`), and preserve explicit `None` values.

### 3.1 Dataclass Schemas

```python
@dataclass
class ProvenanceRecord:
    record_id: str
    source: str
    source_type: str  # 'MODEL', 'RULE_ENGINE', 'OPTIMIZER', 'DOCUMENT'
    stage: str        # 'Stage 2', 'Stage 3', 'Stage 4', 'Stage 5', 'Stage 6'
    model_name: Optional[str] = None
    model_version: Optional[str] = None
    document_name: Optional[str] = None
    data_scope: str = "AUTHORIZED"
    timestamp: str = ...
    metadata: Dict[str, Any] = ...

@dataclass
class EvidenceItem:
    evidence_id: str
    content: str
    source: str
    source_type: str  # 'FORECAST', 'DELAY', 'CONGESTION', 'FEASIBILITY', 'COST', 'OPTIMIZATION', 'DOCUMENT'
    relevance: float = 1.0

    provenance: Optional[ProvenanceRecord] = None

    freight_forecast: Optional[Dict[str, Any]] = None
```

## 4. Safety Validation Engine (`src/agents/safety.py`)

Safety validation helpers enforce hard boundaries before agent responses are presented to users or downstream consumers.

### 4.1 Immutability Verification
`verify_authoritative_immutability(original_context, modified_context)` recursively inspects numerical fields across all stage outputs and flags any numerical modification as a safety violation.

### 4.2 Data Scope Verification
`verify_data_scope(claimed_scope, context)` enforces that `GLOBAL_CONGESTION_PROXY` is never presented as verified Indian port congestion.

### 4.3 Data Unavailability Preservation
`verify_data_unavailability(context, target_dict)` ensures that candidates marked with `DATA_UNAVAILABLE` retain their unverified status and are not assigned fabricated numbers.

### 4.4 Response Text Auditing
`validate_agent_response(response, context)` scans generated agent text using regular expressions to detect and reject:
* Claims of modifying or recalculating freight forecasts
* Claims of calculating custom bunker surcharges or port fees
* Claims of assigning verified physical vessel DWT/LOA/draft
* Claims of converting `DATA_UNAVAILABLE` into numerical values

## 5. Context Builder (`src/agents/context.py`)

`build_agent_context()` constructs an `AgentContext` from Stage 2â€“6 outputs:
* Preserves original numerical values without recalculation.
* Preserves model names and model versions.
* Preserves explicit data scopes (`GLOBAL_CONGESTION_PROXY`).
* Preserves `DATA_UNAVAILABLE` and feasibility status.
* Automatically attaches lineage `ProvenanceRecord` metadata to generated evidence items.

## 6. Provenance & Lineage (`src/agents/provenance.py`)

* `attach_provenance_to_evidence()` links provenance to individual evidence items.
* `extract_provenance_chain()` extracts the complete provenance history across contexts, requests, and responses for auditing.
